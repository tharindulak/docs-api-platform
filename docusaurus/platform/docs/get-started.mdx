# Get Started

Not sure where to begin? This page helps you find the right quick start guide based on what you are trying to do.

## What do you want to do?

### I want to manage and govern APIs
You want the full platform experience: a web console to create, deploy, test, and govern APIs visually.

**If you want WSO2 to host it:**

| Guide | What you will do |
| :--- | :--- |
| [Publish your first API proxy](/api-platform/api-manager/cloud/introduction/quick-start-guide/) | Create a REST API proxy, deploy it, and invoke it from the cloud console. Takes about 10 minutes. |
| [Publish your first LLM proxy](/api-platform/api-manager/cloud/ai-gateway/llm/quick-start-guide/) | Set up a managed proxy to an LLM provider (such as OpenAI) with guardrails and rate limiting through the cloud UI. |
| [Publish your first MCP proxy](/api-platform/api-manager/cloud/ai-gateway/mcp/quick-start-guide/) | Expose a REST API as an MCP tool that AI agents can discover and invoke, configured through the cloud console. |
| [Set up a hybrid gateway](/api-platform/api-manager/cloud/api-platform-gateway/getting-started/) | Connect a self-hosted gateway to the cloud control plane so that API traffic stays in your infrastructure. |

**If you want to run it yourself (API Manager):**

| Guide | What you will do |
| :--- | :--- |
| [Install API Manager](/api-platform/api-manager/install-and-setup/install-and-setup-overview/) | Download and set up API Manager on Docker or Kubernetes. |
| [Publish your first API proxy](/api-platform/api-manager/get-started/api-manager-quick-start-guide/) | Create and deploy an API through the self-managed Publisher UI. |

### I want to run a standalone gateway (no UI, YAML and CLI only)
You want a lightweight gateway that you can download and run immediately. There is no control plane and no web console. Everything is configured through YAML files and CLI.

**For API traffic:**

| Guide | What you will do |
| :--- | :--- |
| [API Gateway: Getting started](/api-platform/api-gateway/1.1.0/quick-start-guide/) | Configure your first API proxy using YAML and start routing traffic. |

**For AI traffic (LLMs and MCP):**

| Guide | What you will do |
| :--- | :--- |
| [LLM Proxy: Quick start](/api-platform/ai-gateway/1.1.0/llm-proxy/quick-start-guide/) | Configure an LLM provider, apply a guardrail, and route your first LLM request. |
| [MCP Proxy: Quick start](/api-platform/ai-gateway/1.1.0/mcp-proxy/quick-start-guide/) | Expose a REST API as an MCP tool and invoke it through an MCP client. |

### I want to govern AI services at the organizational level
You already have gateways running and now want centralized management of LLM providers, MCP servers, guardrails, and cost controls across your organization.

| Guide | What you will do |
| :--- | :--- |
| [AI Workspace: Getting started](/api-platform/api-manager/cloud/ai-workspace/getting-started/) | Set up an AI Workspace, connect it to an AI Gateway, and configure your first LLM provider with guardrails. |

### I want to monetize my APIs
You want to track API usage, set up paid subscription plans, and implement usage-based billing.

| Guide | What you will do |
| :--- | :--- |
| [Monetization: Getting started](analytics-and-monetization/overview.md) | Connect Moesif, create a paid subscription plan, and start tracking API revenue. |
